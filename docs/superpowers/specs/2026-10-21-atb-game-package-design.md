## 1. Executive Summary & Background

### 1.1 The Problem
When HTML5 games generated by `atb-game-porting` (or standard web games) are delivered to end users, they consist of an `index.html` file plus external assets (`assets/` directory containing PNG/JPG sprites, MP3/OGG audio files, and JSON configs, often symlinked via `web/assets -> ../assets`).

If an end user double-clicks `index.html` to open it via the `file:///` protocol without running a local HTTP server:
1. **CORS Network Block**: Browsers block `window.fetch()` and `XMLHttpRequest` from `file:///` (`Cross-Origin Request Blocked: The Same Origin Policy disallows reading the remote resource at file:///...`), preventing JSON level configurations and Web Audio `AudioContext.decodeAudioData()` buffers from loading.
2. **Canvas Tainting (`SecurityError`)**: Drawing external images loaded via `file:///` can taint the canvas, causing subsequent `ctx.getImageData()` or `canvas.toDataURL()` calls to throw uncaught `DOMException: Failed to execute 'getImageData' on 'CanvasRenderingContext2D': The canvas has been tainted by cross-origin data`.
3. **Symlink Failure on Non-POSIX / Non-Git Environments**: Symlinks (`web/assets -> ../assets`) break when zipped or copied across Windows filesystems or downloaded through standard archive extractors.
4. **Friction of Setup**: Requiring non-technical players to install Python/Node.js and run `python3 -m http.server 8000` creates severe distribution friction.

### 1.2 The Goal
Create the `atb-game-package` skill and zero-dependency packaging engine:
- **One-Click Zero-Dependency Delivery**: Automatically bundle any `atb-game-porting` target (`target/<game>/`) or arbitrary HTML5 game directory into:
  1. `<game>-standalone.html`: A single self-contained HTML file with embedded VFS (Virtual File System) and runtime interceptor shim. Double-clicking it in Windows, macOS, Linux, iOS, or Android immediately launches the game in the browser with 0 CORS errors and 0 third-party dependencies.
  2. `<game>-portable/`: A standalone folder with materialized assets (symlinks dereferenced) and zero-dependency native launchers:
     - `Play-macOS.command`: macOS double-click launcher using built-in Python 3/Ruby/PHP to start a local HTTP server and open the default browser.
     - `Play-Windows.bat`: Windows double-click launcher using 100% built-in PowerShell `.NET System.Net.HttpListener` to start a local HTTP server and launch the default browser.
  3. `<game>-release.zip`: An all-in-one distribution archive with Unix executable permission bits (`0755`) preserved on `Play-macOS.command`.
- **Automated `file:///` Verification**: Include `scripts/verify-package.py` to test `<game>-standalone.html` directly in Headless Chrome via `file:///` protocol (without starting an HTTP server), verifying 0 console errors, 0 CORS failures, and $\ge 90\%$ colored pixel ratio across snapshots.

## 2. Ubiquitous Terms & Invariants

- **`Standalone HTML` (`<game>-standalone.html`)**: A single-file bundle that inlines all HTML, CSS, JavaScript, and binary/text assets into Base64 entries, governed by an in-browser VFS runtime shim.
- **`VFS Runtime Shim` (`window.__ATB_VFS__`)**: An in-memory virtual filesystem and API interceptor injected into `<head>` that intercepts `fetch`, `XMLHttpRequest`, `Image.prototype.src`, `Element.prototype.setAttribute`, and `HTMLMediaElement.prototype.src` to serve assets from memory.
- **`Materialized Assets`**: Assets copied as real physical files, completely dereferencing symbolic links like `web/assets -> ../assets`.
- **`Zero-Dependency Invariant`**: The packaging scripts and client-side launchers must require zero external packages:
  - Packaging engine: 100% Python 3 standard library (`base64`, `mimetypes`, `zipfile`, `html.parser`, `shutil`, `json`, `urllib`).
  - Windows launcher: 100% built-in Windows PowerShell (`System.Net.HttpListener`).
  - macOS launcher: 100% built-in POSIX bash script (`python3 -m http.server` with `ruby`/`php` fallbacks).

## 4. Technical Design Details

### 4.1 Single-File VFS Engine (`package-game.py`)

#### 4.1.1 Input Resolution & Asset Discovery
- Probes whether input directory is:
  - A `target/<game>/` directory containing `web/index.html` and optionally `assets/`;
  - A `web/` directory directly containing `index.html`;
  - An arbitrary directory containing `index.html`.
- Traverses all files in the directory and referenced asset folders (e.g., `assets/`, `images/`, `sounds/`, `music/`, `data/`).
- Resolves all symlinks to actual physical targets.
- Computes normalized relative paths as VFS keys (e.g. `assets/images/ball.png`, `assets/levels/level1.json`).

#### 4.1.2 Path Normalization Function (`resolveVfsEntry`)
Inside the browser runtime shim:
```javascript
function normalizePath(rawUrl) {
  if (!rawUrl) return "";
  let clean = rawUrl.split("?")[0].split("#")[0];
  try { clean = decodeURIComponent(clean); } catch (_) {}
  clean = clean.replace(/\\/g, "/");
  // Strip leading file:///, protocol, or absolute root
  clean = clean.replace(/^[a-zA-Z]+:\/\/[^/]*\//, "");
  // Strip leading relative paths ../ and ./
  clean = clean.replace(/^(\.\.\/|\.\/)+/, "");
  return clean;
}
```

#### 4.1.3 Runtime Shim Interception Layer
Injected into `<head>` before any game script executes:
1. **`window.fetch`**:
   - Parses the input URL using `normalizePath`.
   - If present in `window.__ATB_VFS__`:
     - Decodes Base64 to `Uint8Array`.
     - Returns `Promise.resolve(new Response(uint8.buffer, { status: 200, statusText: "OK", headers: { "Content-Type": entry.mime } }))`.
   - If not matched, passes through to native `fetch`.
2. **`XMLHttpRequest`**:
   - Proxies `open()` and `send()`.
   - When matched in VFS:
     - Sets `readyState = 4`, `status = 200`.
     - Fills `responseText`, `response` (as `ArrayBuffer`, `Blob`, `JSON`, or string based on `xhr.responseType`).
     - Emits `readystatechange` and `load` events synchronously or in a microtask.
3. **`HTMLImageElement.prototype.src` & `setAttribute`**:
   - Intercepts property setter: if the assigned value resolves in VFS, sets native `src = "data:" + entry.mime + ";base64," + entry.b64`.
   - Data URIs avoid CORS taint on `<canvas>`, allowing `ctx.getImageData()` without `SecurityError`.
4. **`HTMLMediaElement.prototype.src` & `window.Audio`**:
   - Intercepts `new Audio(src)` and `audioElem.src = ...`.
   - Converts VFS relative paths into `data:audio/...;base64,...` or Blob Object URLs.

#### 4.1.4 HTML, CSS & Script Inlining
- `<link rel="stylesheet" href="...">`: Extracted, `url(...)` targets rewritten to VFS Data URIs, inlined into `<style>` tags.
- `<script src="...">`: Extracted, string-escaped (e.g., `</script>` -> `<\/script>`), inlined into `<script>` tags in exact document order.
- Inlines `window.__ATB_VFS__ = { ... }` as compressed JSON or plain dictionary.

### 4.2 Portable Directory & Zero-Dependency Native Launchers

#### 4.2.1 Directory Structure
In `target/<game>/dist/<game>-portable/`:
- `index.html`: Web entrypoint with relative asset links preserved and symlinks resolved.
- `assets/`: Fully materialized assets directory (no broken symlinks).
- `Play-macOS.command`: macOS launcher script.
- `Play-Windows.bat`: Windows launcher script.
- `README-PLAY.txt`: Quick start instructions in English and Simplified Chinese.

#### 4.2.2 `Play-macOS.command` Specification
- Begins with `#!/usr/bin/env bash`.
- Changes working directory to script parent (`cd "$(dirname "$0")"`).
- Uses Python 3 to find a random free port (`python3 -c "import socket; s=socket.socket(); s.bind(('127.0.0.1', 0)); print(s.getsockname()[1]); s.close()"`).
- Starts background HTTP server: `python3 -m http.server $PORT --bind 127.0.0.1`.
- Calls `open "http://127.0.0.1:$PORT/index.html"`.
- Uses `trap 'kill $SERVER_PID 2>/dev/null; exit 0' EXIT INT TERM` for clean process cleanup.

#### 4.2.3 `Play-Windows.bat` Specification
- Batch script calling Windows built-in PowerShell:
  ```cmd
  @echo off
  powershell -NoProfile -ExecutionPolicy Bypass -Command ^
    "$port = (New-Object System.Net.Sockets.TcpListener([System.Net.IPAddress]::Loopback, 0)); $port.Start(); $p = $port.LocalEndpoint.Port; $port.Stop();" ^
    "Start-Process \"http://127.0.0.1:$p/index.html\";" ^
    "$listener = New-Object System.Net.HttpListener;" ^
    "$listener.Prefixes.Add(\"http://127.0.0.1:$p/\");" ^
    "$listener.Start();" ^
    "Write-Host \"ATB Game Server running at http://127.0.0.1:$p/ (Press Ctrl+C to stop)...\";" ^
    "while ($listener.IsListening) { ... serve static files with proper MIME ... }"
  ```
- 100% zero-dependency on all standard Windows 10/11 installations.

#### 4.2.4 Distribution Zip Archive (`<game>-release.zip`)
- Created using Python `zipfile.ZipFile`.
- Each file entry for `Play-macOS.command` sets `ZipInfo.external_attr = (0o100755 << 16) | 0o20` to preserve executable permission on Unix/macOS after decompression.
- Includes `<game>-standalone.html` at the zip root as well as the `<game>-portable/` directory.

### 4.3 Automated Headless Verification (`verify-package.py`)

#### 4.3.1 Standalone HTML `file:///` Check
- Resolves absolute path to `<game>-standalone.html`.
- Constructs target URL: `file:///<abs_path>?atb_verify_stage=initial|gameplay|stage2`.
- Launches Headless Chrome **directly on the `file:///` URL without running any local HTTP server**.
- Captures snapshots:
  - `dist/snapshots/screen_file_initial.png`
  - `dist/snapshots/screen_file_gameplay.png`
  - `dist/snapshots/screen_file_stage2.png`
- Computes non-black colored pixel ratio using standard-library PNG decoder (threshold $\ge 90\%$).
- Checks Chrome DevTools log for `0` console errors (`CORS`, `Uncaught`, `SecurityError`, `DOMException`).

#### 4.3.2 Portable Package Integrity Check
- Verifies `dist/<game>-portable/` contains no dangling symlinks.
- Verifies `Play-macOS.command` and `Play-Windows.bat` exist.
- Inspects `<game>-release.zip` and asserts `Play-macOS.command` has `0755` executable permissions.
