# Phase 1 & 2: Single-File Bundling & In-Browser VFS Runtime Specification

## 1. Asset Discovery & Symlink Dereferencing
1. **Target Structure Resolution**:
   - For `target/<game>/` ports generated by `atb-game-porting`, automatically recognize `target/<game>/web/index.html` as the web entrypoint and `target/<game>/assets/` (or `web/assets -> ../assets`) as the primary asset store.
   - For custom or third-party web games, locate `index.html` and traverse relative asset directories (`assets/`, `images/`, `sounds/`, `music/`, `data/`, `levels/`).
2. **Deterministic File & MIME Scanning**:
   - Resolve and dereference every file symlink to its physical location on disk.
   - Assign exact MIME types for web graphics (`image/png`, `image/jpeg`, `image/gif`, `image/svg+xml`, `image/webp`), audio (`audio/mpeg`, `audio/ogg`, `audio/wav`), configurations (`application/json`, `application/xml`), and binaries (`application/wasm`, `application/octet-stream`).
   - Encode all file bytes into Base64 strings: `{"mime": mime, "b64": base64_str}`.

## 2. Path Normalization & Canonical VFS Keys
Games frequently request resources with varying relative prefixes, query parameters, or URL encoding (e.g. `"./assets/ball.png?v=1"`, `"../assets/ball.png"`, `"assets/levels/lv%201.json"`):
1. **Normalization Invariants**:
   - Strip URL query strings (`?...`) and fragment identifiers (`#...`).
   - Run `decodeURIComponent()` to resolve encoded characters (such as spaces `%20` or non-ASCII characters).
   - Normalize path separators from `\` to `/`.
   - Strip leading protocol and origin (e.g., `file:///.../`).
   - Strip leading `./` and repeated `../` sequences to match the canonical internal key (e.g. `assets/images/ball.png`).
2. **Multi-Variant Registration**:
   - In `window.__ATB_VFS__`, register the canonical path alongside common relative aliases (`./<path>`, `../<path>`, and `<path>` without `assets/`) to ensure 100% lookup hits.

## 3. Four-Layer VFS Runtime Shim Architecture
The runtime shim is injected at the very top of `<head>` before any game code executes:

1. **`window.fetch` Interceptor**:
   - Intercepts requests for local asset paths.
   - Decodes Base64 to a `Uint8Array` in memory and returns a synthetic `Response` object:
     ```javascript
     var bytes = b64ToUint8(entry.b64);
     var blob = new Blob([bytes], { type: entry.mime });
     return Promise.resolve(new Response(blob, {
       status: 200,
       statusText: "OK",
       headers: { "Content-Type": entry.mime }
     }));
     ```
   - Enables Web Audio API (`fetch(url).then(r => r.arrayBuffer()).then(b => audioCtx.decodeAudioData(b))`) and JSON level loaders to run offline under `file:///` with **zero CORS security violations**.

2. **`XMLHttpRequest` Interceptor**:
   - Hooks `open()` and `send()`.
   - Populates `response` (ArrayBuffer, Blob, JSON, or text depending on `responseType`), `responseText`, and sets `readyState = 4`, `status = 200`.
   - Asynchronously triggers `onreadystatechange`, `onload`, and dispatches `Event("load")`.

3. **`HTMLImageElement.prototype.src` & `Element.prototype.setAttribute` Interceptor**:
   - Hooks the property setter descriptor of `HTMLImageElement.prototype.src` and `Element.prototype.setAttribute("src", val)`.
   - Transparently rewrites relative image paths into same-origin Data URIs (`data:image/png;base64,...`).
   - **Zero Tainted Canvas Guarantee**: Drawing Data URI images onto `<canvas>` does not taint the canvas context under modern browser security models, enabling `ctx.getImageData()` and `canvas.toDataURL()` to succeed without `SecurityError`.

4. **`HTMLMediaElement.prototype.src` & `window.Audio` Interceptor**:
   - Intercepts `new Audio(src)` and audio element `src` assignments, redirecting relative paths to Base64 audio Data URIs (`data:audio/mpeg;base64,...`).
